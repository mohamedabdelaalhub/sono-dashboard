# تفعيل خدمة التحليل الآمنة

ملفات الواجهة تكتشف هذه الوظيفة عند تسجيل الدخول وتستخدمها بدل استلام مفتاح المزوّد.
حتى نشر الوظيفة يبقى المسار الحالي فعالًا. نقل المفتاح إلى الخادم لا يكتمل بمجرد نشر GitHub Pages.

ترتيب التفعيل داخل مشروع Supabase المرتبط بالداشبورد

1. انشر الوظيفة `dashboard-ai` من `index.ts` و`validation.mjs` مع التحقق من JWT.
2. طبّق `supabase/migration-secure-ai.sql` في SQL Editor. المفتاح الموجود يبقى داخل `app_secrets`، لكن المتصفح يفقد حق قراءته.
3. سجّل الخروج ثم الدخول. اختبر السوبر أدمن والمستخدم المصرّح والمستخدم غير المصرّح.
4. تأكد أن رد الوظيفة يحتوي النص فقط، وأن `get_ai_key` وقراءة `app_secrets` مرفوضان للمستخدمين.

الوظيفة تتحقق من المستخدم والدور في الخادم، وتحدد خمس طلبات في الدقيقة لكل حساب، وتمنع اختيار مزوّد أو نموذج من الطلب نفسه.
لا تدخل service role key في الواجهة أو ملفات الموقع.

النشر عبر CLI بعد تسجيل الدخول إلى الحساب وربط المشروع

```bash
supabase functions deploy dashboard-ai
```

إذا فشل اختبار التفعيل، أصلح الوظيفة قبل إلغاء قيود قراءة المفتاح. لا تعِد المفتاح إلى المتصفح.
