# تفعيل مشاركة دراسات الفروع

شغّل `migration-branch-sharing.sql` في SQL Editor لمشروع Supabase المتصل بالداشبورد. التحديث ينقل الدراسات القديمة الصالحة من جدول التقارير إلى جدول مستقل مع الاحتفاظ بمعرّفاتها وصاحب الدراسة. لا تعدّل `config.js`.

بعد نجاح التنفيذ افتح الحاسبة واضغط «مزامنة الحساب»، ثم افتح الدراسة. صاحبها والسوبر أدمن يمكنهما إضافة مستخدم من الحسابات النشطة وتحديد صلاحياته:

| الصلاحية | ما تسمح به |
| --- | --- |
| استعراض فقط | فتح الدراسة دون حفظ تغييرات |
| إضافة | إضافة أقسام وبنود جديدة دون تغيير البنود المحفوظة |
| تعديل | تعديل الاسم والقيم الموجودة دون إضافة أو حذف بنود |
| كل الصلاحيات | إضافة وتعديل وحذف الأقسام والبنود |

إدارة المشاركين وحذف الدراسة بالكامل لصاحب الدراسة والسوبر أدمن. السوبر أدمن يرى كل الدراسات تلقائياً. إلغاء الوصول يمنع الطلبات التالية فوراً؛ النسخ الاحتياطية التي نُزّلت سابقاً لا يمكن سحبها من جهاز المستخدم.

زر حفظ الدراسة يرسل التعديلات للحساب. المسودة أثناء الكتابة تحفظ محلياً فقط. على الجهاز الآخر اضغط المزامنة وافتح آخر نسخة. إذا عدّل جهازان نفس النسخة، يُرفض الحفظ الأقدم لتجنب فقد التغييرات، وتُحفظ نسخة الجهاز عند المزامنة إذا كانت الدراسة المحفوظة محلياً مختلفة عن آخر نسخة على الحساب.

على Mac يمكن فتح `تفعيل-حماية-الذكاء.command` لتجهيز نشر وظيفة الذكاء الاصطناعي ونسخ تحديثَي قاعدة البيانات. تسجيل الدخول إلى Supabase وتنفيذ SQL يحتاجان حساب مالك المشروع. نجاح GitHub Pages وحده لا يفعّل تحديث قاعدة البيانات أو وظيفة الذكاء الاصطناعي.

التحقق قبل النشر: `NODE_PATH=<dependencies>/node_modules node tests/branch-sharing.cjs` يشغّل SQL فعلياً في PostgreSQL محلي ويختبر الصلاحيات، الإجماليات، التعارضات ومنع الوصول المباشر. `tests/calculator-sharing.cjs` يختبر واجهة القائمة والمشاركة.
